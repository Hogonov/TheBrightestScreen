# TheBrightestScreen

Бесплатное локальное приложение для повышения яркости Apple XDR на macOS 13+. Сборка для Apple Silicon, без зависимостей, подписки и сети.

## Запуск

Откройте `build/Brighter.app`. В строке меню появится солнце; меню открывается по нажатию на него. Нажмите **Максимальная яркость**: Brighter выставит системную яркость на 100% и включит XDR. При обычном запуске усиление выключено. При желании скопируйте приложение в «Программы».

Версия 1.0.1 использует отдельный постоянный идентификатор `local.alexandr.BrighterStandalone`. Это обходит старую ошибочную привязку значка к ChatGPT в Control Center macOS Tahoe. Перед первым запуском обновления закройте предыдущую версию через «Выключить и выйти». macOS может сохранить старую строку Brighter в настройках менюбарa; новая версия зарегистрирована отдельно. Защищённые системные настройки приложение не редактирует.

Пока приложение работает, значок включён независимо от состояния XDR. Его случайное удаление перетаскиванием запрещено, а сброс видимости автоматически исправляется без повторного запуска. При нехватке места macOS всё же может скрыть значок — приложение не может гарантировать место в переполненной строке меню.

Если солнца не видно, откройте `Brighter.app` ещё раз: приложение восстановит видимость значка и откроет меню управления рядом с курсором. Это работает и при переполненной строке меню, когда macOS не оставляет места для значка. Повторный запуск сохраняет текущее состояние яркости.

- **Включить XDR** повышает диапазон яркости, сохраняя текущую системную настройку.
- **Усиление XDR** регулирует дополнительное усиление от 0 до 100% (это не измерение яркости в нитах).
- **Выключить XDR** возвращает исходную гамму и системную яркость, если она всё ещё на выставленном приложением максимуме. Изменения клавишами яркости сохраняются.
- **Выключить и выйти** восстанавливает настройки и закрывает приложение.
- Сначала закройте BrightXDR, Vivid или BrightIntosh, если они запущены.

## Сборка и проверка

Нужны Xcode Command Line Tools и macOS. Перед сборкой закройте Brighter. Готовое приложение запускайте двойным щелчком в Finder по `build/Brighter.app`, чтобы оно регистрировалось отдельно от среды разработки. Сборка сама приложение не запускает.

```sh
bash scripts/build.sh
bash scripts/test.sh
bash scripts/test-menu.sh
bash scripts/build.sh --test
build/BrighterDiagnostics.app/Contents/MacOS/Brighter --diagnose
build/BrighterDiagnostics.app/Contents/MacOS/Brighter --smoke-test
```

`--diagnose` только читает состояние. `--smoke-test` на 9 секунд включает максимум, проверяет реальное применение гаммы, ограниченный размер окон и восстановление, затем завершает процесс. Перед этим закройте уже запущенный Brighter. Этот тест вызывает обработчик смены Spaces, но сам рабочие столы не переключает. В рабочей сборке запуск `--smoke-test` запрещён: используйте диагностическую сборку с отдельным идентификатором `local.alexandr.Brighter.Diagnostics`.

`scripts/test-menu.sh` требует графическую сессию macOS: проверяет запуск без всплывающего меню, автоматическое восстановление скрытого значка без повторного открытия, запрет удаления значка и меню при повторном открытии, не включая усиление яркости. Тест запускается в отдельном `BrighterMenuTests.app` с идентификатором `local.alexandr.Brighter.MenuTests`. Тесты не используют идентификатор рабочего приложения, чтобы запуски из терминала или AI-среды не связывали его значок с родительским приложением.

Для проверки конкретной системы включите максимум, несколько раз переключите Spaces и полноэкранное приложение, откройте/закройте Mission Control, затем выключите XDR. Физическую яркость и отсутствие кратких вспышек следует оценивать на самом дисплее: скриншот не измеряет ниты.

Опция `--enable` запускает сразу с максимальной яркостью; передавайте её через LaunchServices (`open build/Brighter.app --args --enable`), а не прямым запуском исполняемого файла рабочей сборки из среды разработки. Автозапуск не включается автоматически. `SIGTERM`, `SIGINT`, `SIGHUP` обрабатываются с восстановлением состояния; после принудительного `SIGKILL` восстановление системного ползунка не гарантируется.

Сборка подписана локальной ad-hoc подписью, без Apple notarization. Исходный код и лицензия приложены. Основано на подходе [BrightIntosh](https://github.com/niklasr22/BrightIntosh); см. `THIRD_PARTY_NOTICES.md` и `LICENSE`.
